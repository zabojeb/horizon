# Performance gaps: what was fixed, what is left (31 October 2026)

A read of the server tick, the network path and single player's memory connection for CPU work that
vanilla's results don't need. Every fix here keeps what goes on the wire and what the game does: the same
bytes, the same order, the same random draws. The measurements are micro-benchmarks on one x86_64 machine
(4 cores, AES-NI), release profile, before and after on the same build.

## Fixed in this change

| Where | What was slow | Fix | Measured |
|---|---|---|---|
| `horizon-protocol/src/connection.rs` `Pipe` (single player's memory connection, the gym) | Every byte copied one at a time; every write woke the reader with a system call; a mutex locked on every read for the timeout | Copy the queue's two halves whole; wake the reader only when the queue was empty (it waits only then); the timeout in an atomic | with the frame fix below: 40-byte packets 664k → 3,047k a second (×4.6), 1 KB 160k → 1,425k (×8.9), 60 KB chunks 357 → 723 MB/s (×2), small packets with compression on 558k → 6,402k (×11) |
| `connection.rs` `ConnReader::recv`, `frame.rs` (every connection's receive path) | Each frame moved the rest of the 16 KB read buffer to its front (quadratic in the packets per read) and was copied three times | A cursor into the buffer, compacted once no whole frame is left; uncompressed frames borrowed (`frame::decompressed`), one copy for the payload | (above) |
| `horizon-protocol/src/crypto.rs` `Cfb8` (online mode: every byte to and from every player) | A byte-wise AES: one full block encryption per byte, 4.2–4.7 MB/s each way | The `aes` crate's block cipher (AES-NI or ARMv8 AES, found at run time; constant-time software elsewhere); decryption encrypts its registers 64 at a time, since they are ciphertext already received | encrypt 4.4 → 42 MB/s (×10), decrypt 4.4 → 232 MB/s (×50). At 100 players and ~95 KB/s each, encryption fell from about 2 cores to 0.2 |
| `connection.rs` `ConnWriter::begin_batch`, `lan/conn.rs` `write_loop` | A tick's packets for one player written one `write` each: a system call and, with `TCP_NODELAY`, a TCP segment per packet | The tick's frames framed and encrypted into one buffer, written once; the byte stream is the same (CFB8 is a stream cipher), only its segments are fewer | one system call per player per tick instead of one per packet |
| `horizon-core/src/ticks` (`ChunkTicks`, `LevelTicks`, `ProtoChunkTicks`) | SipHash on every schedule attempt and lookup of `(type, position)` and chunk keys | The Fx hash (`horizon_core::fast_hash`, moved down from `horizon-client-render`). None of these maps' orders is observable: `chunks_in_area` sorts, the rest is membership, and the default hasher's order was random anyway | schedule-and-run cycle 10 → 17–19 M a second (×1.7) |
| `mobs.rs` `blocks_changed`, `game/creatures.rs` | Every navigating mob compared two collision shapes for every block write of the tick (mobs × writes shape lookups) | `shape_changes` once per tick (the world is the same for every mob), then each mob tests only its path against the changed positions | not measured; exact by construction (both tests are pure) |
| `mobs/living.rs` `supporting_block` (every grounded mob, every tick) | Re-read the block it had just read, and collected its collision boxes into a `Vec` to test them | `collision_meets`: the state already read, the boxes tested in place | not measured |
| `--gym` clients (game/gym.rs) | A client that never draws meshed every section and simulated particles, rain splashes and block animations | Meshing off (`Streaming::mesh`), no particle simulation | not measured (no prepared resources on the machine) |

## Left to do, by expected impact

Estimates from reading the code at 100 players with about 1,800 mobs; none is measured yet. Each needs the
bench of [server-next.md](../server-next.md) to show its gain and the harnesses that cover its area.

**Server tick**

1. **Collision scans rebuild every shape they hit** (`horizon-world/src/block_collision_scan.rs` `find_next`,
   `shape.rs` `moved`): about seven allocations and sixteen atomic operations per block a moving entity touches.
   Return the block's shape and offset instead of a moved copy, and add the offset where a coordinate is read
   (the same `c + o`, so the same bits).
2. **Every mob, and every spawning chunk, scans every player** (`creatures.rs` `nearest_player`,
   `lan_mobs.rs` `choose`, `spawn_selection.rs` `players_near`), and clones a `PlayerView` per mob. One player grid
   per tick, read 3x3 cells, keeping the lowest index among equal distances, gives the same answers.
3. **Every block read hashes the chunk map** (`horizon-client-render/src/world.rs` `World::block`), 135 call sites
   in `mobs/` alone. Vanilla's `ServerChunkCache` keeps a four-entry last-chunk cache; a read-only wrapper with one
   (`Cell` inside the mob loop's borrow) would do the same.
4. **Natural spawning builds strings per attempt** (`spawn_rules.rs` `format!("minecraft:{}")`, SipHash lookups
   of placements and tags, `weighted_pick` cloning a `String`). A placement table per species and a bit per
   state for the `*_spawnable_on` tags.
5. **Fluids repeat passability tests** (`level/fluids.rs` `slope_distance`: up to 480 calls for at most 244
   distinct cell and direction pairs). Memoize per cell and direction in `SpreadContext`; `spread_targets`
   can use a fixed array instead of a sorted `Vec`.
6. **Four scans of each mob's box per tick** (`ai.rs` `effects_from_blocks`, `motion/environment.rs`
   `fire_contact`, `motion/fluids.rs` `bubble_column_push`, `ai.rs` `in_powder_snow`), each a block name compare
   per cell. One palette check over the box first (`World::may_hold`), as `fluids()` already does.
7. **Random ticks read light twice and look chunks up ten times per ticking chunk** (`level/mod.rs`
   `raw_brightness`, `game.rs` `ticking_chunk`).

**Network**

8. **Large bodies are copied, hashed and compressed once per recipient** (`lan/hub.rs` `update_chunks`,
   `lan/conn.rs` `SharedFrames::contents`): share the compressed frame among the writers that send it.
9. **Entity tracking clones every encoded body for every viewer** (`lan/entity.rs`); an append buffer per viewer,
   which the batched write above can take whole.
10. **The client finds an entity by scanning its mob list** for each packet that names one (`game/remote.rs`
    `move_entity`, `SetEntityData`, `SetEquipment`): an id-to-index map.
11. **Loading or forgetting a column scans every block entity** (`remote.rs`, `remote_chunks.rs`): an index by
    column.
12. A deflate state is created per compressed packet (`frame.rs` `contents`): keep one per writer and `reset()`.

**Memory and start**

13. The gym and a dedicated server load what only drawing needs (block models, GUI atlases, entity models); the
    dedicated server already skips some. See [server-next.md](../server-next.md) section 7 for the plan below
    Pumpkin's 32 MB idle.
